---
name: feishu-debate
description: 用户明确要求正反双方独立辩论（包括“辩论话题：…”）时，在飞书任务内组织各五轮辩论并逐轮推送。双方分别使用独立 Codex 调用与各自历史，只交换最终发言。
---

优先调用当前任务已提供的 `feishu_bot` MCP `debate` 工具，参数 `topic` 为用户辩题；该通道不经过用户任务的 shell 沙箱。

主机 CLI 兼容入口：

```bash
"$FEISHU_TOOL_CLI" debate --topic '用户的辩题'
```

`python3 "$FEISHU_DEBATE_SCRIPT" --topic '用户的辩题'` 调用相同工具。只读沙箱在 Linux 上可能禁用 Unix socket，CLI 出现 `Operation not permitted` 时使用已提供的 MCP 工具。不要直接在任务沙箱内再启动辩手 Codex：任务沙箱没有网络。MCP 适配器通过任务令牌路由到机器人，由机器人执行内部模型调用；用户任务仍保留原来的只读或工作区权限。

工具为正反双方各执行5轮，每条最终发言回复当前飞书消息。双方分别保留自己的历史，只交换对方最终发言，不共享推理内容。内部调用关闭外部工具，不落 bot 会话表，使用一次性 CLI 上下文。只把本轮辩题交给工具，不要让单个上下文自己扮演双方。

等待同步返回；只有 `ok=true`、`result.completed=true` 且10条发言完成才能声称独立辩论完成。工具总时限不超过当前任务剩余时间；任务取消后停止辩手与推送。

工具失败即停止，如实说明独立辩论未完成、已完成轮次及错误。不自动重跑整场，不用单模型模拟补齐，不自行开启 `/permit` 或 `/unsafe`。最终回复根据实际成功发言简述核心分歧与结论。

用户只是查询辩论模式、排查技能或阅读代码时，不启动辩论。
